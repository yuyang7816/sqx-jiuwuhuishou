# 管理端功能说明

管理端是给平台工作人员用的网站，在电脑浏览器里打开。预约回收的用户不使用这个网站。它用来维护回收品类和价格、处理订单和取件、审核结算打款、配置首页和福利，以及填写微信、支付宝、短信、顺丰这些外面服务的账号。

程序里的名称是「旧物回收管理后台」。工作人员登录后，左侧是菜单。能看到哪些菜单，由管理员给这个账号分配的权限决定。没有权限的菜单不会出现。

下面的菜单名称来自项目里的页面。如果你后来在「菜单管理」里改过名字，以你屏幕上看到的为准。

## 登录

登录页要填账号、密码，还要看一张图片验证码。看不清就点图片换一张。验证码由服务端生成。服务端没启动时，图片是裂的，登录也会失败。

登录页源码注释里的演示账号是 `admin`，密码是 `123456`。这和 MySQL 的 root 密码不是同一个。`jiuwuhuishou-server/sql` 里的脚本不负责创建这个管理员。库里还没有系统用户时，用这个账号会登录失败。

## 登录之后第一眼：数据中心

左侧「数据中心」就是登录后的首页。这里看平台现在的概况，数字来自自己的数据库，不连接外面的报表公司。

可以按今日、近 7 日、近 30 日，或自己选一段时间。页面上常见这些数字：

- **订单量**
- **成交额 GMV**
- **完成率**、**取消率**
- **待处理积压**
- **新增用户**
- **价差（实-估）**：实际成交和预估之间的差额
- **打款成功率**

下面还有待确认结算、待打款、取件任务（待上门、取件中、已完成、超时）、异常和争议、评价均分、提现审核、佣金发放、签到人数。它用来知道有没有新订单和待处理事项，不是在这里替用户付款。

## 用户中心

看在旧物回收里注册的用户。可以点进用户详情，看这个人的账号资料。

这里管的是在手机或网页里注册的人。后台工作人员的登录账号在「系统管理 → 管理员管理」，不要混在一起。用户还没在用户端注册过时，这个列表里不会凭空出现顾客。回收员也是这里的用户，用户类型为员工后，用户端才会出现「我的取件」。

## 业务管理

### 用户地址

查看用户保存的上门地址和取件地址，包括联系人、电话、省市区和是否默认。用户在手机里新增的地址会出现在这里。

### 回收订单

查看用户提交的回收单。可以按状态看进行中、待确认、已完成等订单，点进详情处理履约。邮寄单可以在这里确认收件、看运单号。用户端订单列表读的就是这些数据。

### 改约记录、异常工单

用户在订单里改上门时间，或反馈异常之后，记录出现在这两个菜单。用来跟进改期和异常，不是再下一笔新订单。

### 取件任务

把上门订单分给回收员，查看待上门、取件中、已完成。回收员在用户端「我的取件」里看到的任务来自这里。完成取件时回填的成交金额，会回到订单上，作为后续结算的依据。

### 结算管理、打款管理、争议工单

- **结算**：用户确认或争议实际成交价。待确认的单会等用户在手机里点接受。
- **打款**：审核通过后，把回收款记入用户钱包。没配微信、支付宝商户时，平台内余额可以入账，提现到微信或支付宝完不成。
- **争议**：用户不接受成交价时提交的工单。处理结果会回到这张订单。

### 评价管理

查看用户完成后的评分和投诉类型，工作人员可以回复。用户端订单完成后的「评价投诉」写到这里。

### 回收品类、回收品类主数据

维护用户能看到的入口，例如家电、数码、旧衣、奢侈品、书籍，以及下面的品牌、型号、规格。用户端首页品类、数码搜索、奢侈品品牌，读的就是这些数据。

### 服务区域、回收规则、回收配置

- **服务区域**：哪些城市或地址可以上门。用户端「服务范围与规则」里的覆盖查询用这里的数据。
- **回收规则**：家电等品类的计价说明、不可回收项、服务费。用户端「回收规则详情」展示这些内容。
- **回收配置**：旧衣单价、书籍重量档、可预约天数、首页流程图标等页面上的业务参数。

### 首页装修

决定用户端首页的轮播图、公告和入口跳转。改完保存后，用户下次打开首页才会变。图片存在本机还是阿里云，由系统配置里的存储方式决定。

### 消息管理、帮助中心

给用户发系统通知，以及维护帮助分类和文章。用户端「消息通知」「帮助中心」读这里。

### 品牌合作、福利任务、用户福利

- **品牌合作**：查看用户提交的合作意向。
- **福利任务**：配置签到、邀请等任务的名称、奖励和图标。
- **用户福利**：查看用户金币、签到情况。签到奖励进的是平台积分，不直接打到微信。

### 在线客服、客服配置

查看用户发来的会话并回复。快捷问题、轮询间隔等在客服配置里改。双方消息存在自己的数据库里，不经过外面的客服公司。

### 用户钱包、钱包流水

查看余额、待入账和每一笔流水。回收打款、佣金、积分兑换入账后，用户在「我的」里看到的余额来自这里。

### 分销佣金、用户佣金汇总

查看邀请关系和佣金。比例在系统配置里改。用户端邀请海报和「我的推荐」用的是同一套数据。

### 提现记录、提现账户

审核用户把钱包余额提到微信或支付宝的申请，并查看收款码或支付宝账号。审核通过只表示平台同意这笔申请。真正打到微信或支付宝，还要支付密钥可用。

### 短信模板

维护注册、找回密码等短信文案。测试模式开着时，用户端验证码固定是 `888888`，模板不会真正发出去。

## 系统管理

「系统管理」是给工作人员账号用的，预约回收的用户看不到：

- **管理员管理**：后台登录账号。和「用户中心」里的回收用户不是同一张名单。
- **角色管理**、**菜单管理**、**权限管理**：决定某个工作人员登录后能看见哪些菜单、能点哪些按钮。
- **字典管理**：下拉选项一类的基础数据。
- **系统配置**、**配置分组**：微信、支付宝、短信、上传、顺丰、物流查询、协议文本、验证码是否测试模式，都在这里填。不填密钥时，对应的外部能力只停留在页面上。
- **操作日志**：工作人员在后台做了哪些操作。

## 和外面服务的关系

管理端自己不直接向用户微信付款。它把密钥和开关存进数据库，等用户端或服务端真正发起短信、支付、寄件时再使用。

存储方式保持「本地」时，上传的轮播图和收款码保存在运行服务端的那台电脑上。改成阿里云之后，必须同时填对密钥和空间地址，否则用户端图片会裂。
