# 服务端功能说明

服务端没有给预约回收的人点的页面。它是一台一直开着的程序：手机上的「旧物回收」和电脑上的「旧物回收管理后台」把登录、估价、下单、打款这些请求发给它。它检查这个人能不能做这件事，把结果记进数据库，需要时再去问微信、支付宝、短信、顺丰这些外面的服务。

可以把它理解成总台。两个前台说的话，都由总台记账，并在需要时给外面的公司打电话。

代码在 `jiuwuhuishou-server`。启动类是 `com.sqx.SqxApplication`。端口是 **9135**，所有接口都在 `/sqx_fast` 下面。接口列表在：

http://127.0.0.1:9135/sqx_fast/doc.html

文档标题是「旧物回收系统接口文档」。这个页面给开发和排查接口用，用户不打开它。

数据库配置在 `sqx-application/src/main/resources/application-dev.yml`。自己电脑上用的库名是 `jiuwuhuishou`。业务表脚本在 `jiuwuhuishou-server/sql`，从 `V1__recycle_init.sql` 起按版本导入。品类、订单、取件、钱包、福利都记在这个库里。管理员和菜单不属于这批业务脚本。

`application.yml` 里 `sqx.redis.open` 是 `false`。本地默认不连 Redis，第一次把程序跑起来可以先不装它。登录凭证靠服务端发给用户的那张票，存在用户端本地，并在每次请求时带上。

`sqx.verify-code.test-mode` 现在是 `true`，短信验证码固定为 `888888`。这是为了本地能注册，不代表短信已经接通。

下面按「用户点一下，服务端做了什么」「回收员点一下，服务端做了什么」「管理端点一下，服务端做了什么」来写。最后说明哪些事会真的连到微信、支付宝、短信和顺丰。

## 它为预约回收的用户做的事

这些都是用户在手机或网页里点一下之后，由服务端完成的。

### 注册和登录

网页上注册、找回密码要手机号和短信验证码。测试模式开着时，服务端认 `888888`，不向短信公司发请求。微信小程序里先做微信授权，再授权手机号，服务端把微信身份和手机号对上，再发登录凭证。网页日常登录是手机号加密码。

凭证通过之后，下单、看钱包、提现都要带上它。没带，服务端就当成没登录，并让页面先去登录。

管理端登录页上的图片验证码也由服务端生成。那是给工作人员用的，和用户的短信验证码不是同一个东西。

### 首页

用户打开首页时，服务端把这些内容交回去：

- 轮播图：图片、标题、点下去跳到哪里。
- 推送提醒文案。
- 成交公告。
- 品类入口：家电、数码、旧衣、奢侈品、书籍。具体有哪几个，以后台配的为准。
- 推荐分佣和福利任务入口。

这些都来自自己的数据库。服务端没启动，或用户端仍指向线上域名时，手机上看不到你本机刚改的那一条。

### 估价和下单

- **家电**：按品类、型号、成色算出预估区间，再保存上门或寄件订单。
- **数码、奢侈品**：按品牌和规格搜索，算出参考价后下单。
- **旧衣、书籍**：按品类单价或重量档估算，再写入预约地址和时段。
- **地址**：省市区和门牌存在自己的库里。选择省市区用的是项目自带的地区数据，不向地图公司要坐标。
- **服务范围**：按后台配置的区域判断这个地址能不能上门。

预估价只是下单时的参考。实际成交金额以后续质检或回收员回填为准。

### 订单之后

- 改约、取消、异常反馈，都是改这张订单的状态，并留下记录。
- 邮寄单可以补运单号。配置了顺丰或物流查询之后，服务端才去外面查轨迹。
- 结算确认：用户接受成交价，或提交价格争议。
- 打款：审核通过后把金额记入用户钱包，并写下流水。
- 评价：保存评分和投诉类型。

订单状态以数据库里的记录为准。用户把页面关掉，不会取消已经提交成功的订单。

### 福利、钱包、会员、邀请

- **签到和任务**：增加金币，记在福利账户里。
- **积分兑换**：按配置的比例，把金币换成钱包余额。
- **提现**：记下微信收款码或支付宝账号，生成一条待审核记录。审核通过并且支付密钥可用时，才会向微信或支付宝发起打款。
- **会员**：创建开通订单。走微信支付时，要等微信通知服务端，会员才会生效。
- **邀请**：生成邀请关系。好友完成回收后，按配置比例记佣金，佣金可以再进钱包。

### 客服和帮助

在线客服的消息通过服务端转发，并保存在自己的库里。帮助文章、协议、关于我们，也是后台写进库、再由服务端读出来。

## 它为回收员做的事

回收员不是另一套登录系统。后台把某个用户标成员工后，用户端才出现「我的取件」。

- 按待上门、取件中、已完成返回任务列表。
- 开始上门、完成取件时更新任务状态。
- 完成时保存实际成交金额，供用户确认和后续打款使用。
- 联系电话来自订单上的用户手机号，拨号由手机自己完成，服务端不替双方接通电话。

员工账号不能在用户端自己申请。

## 它为管理端做的事

工作人员在电脑后台的每一下保存，都是在调用服务端：

- 登录时校验账号、密码和图片验证码，再按角色返回能看的菜单。
- 数据中心把订单量、成交额、完成率、取件、打款、争议、评价、佣金、签到汇总出来。
- 品类、规则、服务区域、首页装修、福利任务，改的是用户端下次打开会读到的那些表。
- 订单、改约、异常、取件、结算、打款、争议、评价，改的是同一张业务单的后续状态。
- 钱包、佣金、提现审核，改的是用户余额和审核状态。
- 系统配置把微信、支付宝、短信、上传、顺丰的密钥存进数据库。服务端在对应用户动作发生时才拿出来用。

管理端不会绕过服务端，自己直接改数据库。页面上看到的列表，都是服务端查库之后返回的。

## 哪些事会连到外面

| 能力 | 什么时候才会出去 | 没配好时怎么样 |
|---|---|---|
| 短信 | `test-mode` 为 `false`，并且短信通道的账号已填写 | 测试模式下验证码一直是 `888888` |
| 微信登录、微信支付 | 小程序 AppId、Secret、商户号已填写，并且用户在微信里打开 | 登录或付款停在授权失败 |
| 支付宝 | 应用私钥等已填写 | 提现或支付请求到不了支付宝 |
| 顺丰寄件、物流轨迹 | 顺丰或物流查询的密钥已填写 | 运单号可以保存，轨迹是空的 |
| 阿里云图片 | 存储类型改成阿里云且密钥正确 | 建议保持本地存储，图片在运行服务端的电脑上 |
| 在线客服 | 不需要外面的客服公司 | 消息只在自己的服务端和数据库之间 |

支付结果以服务端收到的通知为准。用户付完钱立刻关掉页面时，订单或会员可能要等通知到了才变。

## 代码大致放在哪

业务代码在 `sqx-modules/sqx-app/src/main/java/com/sqx/app`：

- `recycle`、`product`：品类、估价、规则
- `order`：回收订单、预约时段、状态
- `pickup`：取件任务
- `express`：顺丰和物流查询
- `settlement`、`payout`：结算和打款
- `wallet`、`welfare`、`vip`、`referral`：钱包、积分、会员、佣金
- `servicechat`、`help`、`brand`：客服、帮助、品牌合作
- `admin`：给管理端用的订单和审核接口
- `base`：登录、验证码、轮播、系统配置读取

管理员、角色、菜单在 `sqx-modules/sqx-system`。支付、短信、上传、Redis 在 `sqx-common` 下面对应的模块里。
